# 30-tank frame sweep on main a2fc93f, and an unexplained 3× gap

MEASURED on 2026-10-29, Apple M4 (MacBook Pro, Mac16,1). Release build of `a2fc93f`, run with `scripts/perf/run-frame-sweep.sh`: visible window, quiet machine, AC power, every validity gate passed.

Three sweeps agree to within 0.2 ms:
- `sweep-30`, with an external 100 Hz monitor connected and ThreatLight's process monitor running;
- `sweep-30b`, with ThreatLight and Dia stopped;
- `sweep-30c`, with the external monitor unplugged and the window born on the built-in display.

`sweep-30c` (p50 / p95 ms):

| Shadows | 2 tanks | 30 tanks |
|---|---|---|
| M350 (shipped) | 14.59 / 17.72 | 19.16 / 25.04 |
| Off | 12.33 / 16.80 | 16.36 / 20.29 |
| M1000 | 14.55 / 16.92 | 19.11 / 24.97 |

- 30 tanks add +4.56 ms at p50 over 2 tanks.
- Shadows off saves 2.26 ms at p50 with 2 tanks.

## The gap

At about 03:45 the same binary in the same duel scene measured 5.72 ms p50 (`runs/forest/duel-trees`). In the evening it measured 14.51 ms (`runs/ab-A1` to `ab-A2`, in A-B-B-A order: the old and new builds are equal, so the code is cleared).

Ruled out by measurement:
- the binary or code (A-B-B-A equal);
- ThreatLight and Dia (`sweep-30b`);
- the external monitor and the window's birth display (`sweep-30c`);
- idle GPU load (4–6 %);
- low power mode (off);
- thermal warnings (none recorded).

**The one logged difference** between the fast morning runs and the slow evening runs: the morning client logged `state: focus lost — pause suppressed`, so the game window did NOT have keyboard focus. The evening runs had focus.

**Hypothesis:** something that runs only while the game window has focus costs about 9 ms per frame. Suspects are the input and aim path, for example the aim ray across the terrain heightfield. It is untested.
