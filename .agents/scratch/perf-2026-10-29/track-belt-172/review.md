## Ranked findings
1. MEDIUM — `src/track/belt_draw.rs:157-219` GPU memory per link count, never freed. MEASURED (tiger_1.glb accessors): shoe V = 2273/1673/1137/754/498, indices 4560/1968/1200/756/498 over 5 rungs. DERIVED at 52 B/vertex (ASSUMED packing: pos 12, normal 12, uv 8, tangent 16, link 4) × 97 links: 35.4 MB per side, **70.9 MB per link count**, against ~0.6 MB for the shared shoe meshes before. `by_count` is never evicted: each count the sandbox `;`/`'` knob visits keeps its set, and each vehicle with a distinct count adds a set. `ensure` builds the whole set on the main thread in one bind (~71 MB of allocations, then the extraction copy; the hitch is unmeasured). The README names this cost but gives no number. Fix: quote the number; evict counts no live belt uses; build rungs lazily; longer term, use vertex pulling (link = vertex_index / V) so memory no longer scales with count.
2. LOW — `belt_draw.rs:179-219` refusal is never latched. If rung k returns `None` (a non-float attribute at :265, or non-f32x3 positions at :196, which logs nothing), rungs 0..k-1 are already built and `meshes.add`ed (:205-206) and then dropped. With nothing cached, `bind_track_rigs` and `sync_link_pool` redo that work every frame, `error_once` hides it, and no tank ever gets a track. It is latent: the shipped shoe carries only NORMAL/POSITION/TANGENT/TEXCOORD_0 (MEASURED); a tank #2 shoe with an integer attribute would trip it. Fix: validate every rung before building anything, and cache the refusal per count.
3. LOW — `belt_draw.rs:383-387` and `view.rs:66`: `BeltUpload` has no edge to `AssetEventSystems` (bevy_asset 0.19.1 lib.rs:662-665). A `ShaderBuffer` reaches the render world only through its AssetEvent (bevy_render render_asset.rs:303-317). In the game the upload currently wins on readiness timing alone: `AssetEventSystems` comes after Propagate→`GunnerCameraPlaced`→`CameraUpdateSystems` (camera.rs:244-250, bevy_render camera.rs:76-78) (DERIVED). The sandbox has no such chain. If the event flushes first, the first change after a quiet frame draws last frame's spans while the hull, wheels, Aabb and prints are current. Triggers: a teleport or respawn of a parked tank, or motion onset; the x-ray look shares the buffer. Continuous motion hides it. view.rs:65 claims "in the frame the view fits it" and nothing enforces it. Fix: `BeltUpload.before(AssetEventSystems)` (check for cycles).
