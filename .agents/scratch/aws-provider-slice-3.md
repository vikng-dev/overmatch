# Hosting slice 3: EC2 provider

Built in `lane/aws-provider`, bay-3. Subject: hosting for the Overmatch multiplayer video game.
No AWS write, deployment, key handoff, quota request or external comment was made. The only live
AWS reads were the public image parameter and its image description, through the operator's
`overmatch` profile in `ap-southeast-1`; output contained only the root device, size and type.

## Result and requests

`PROVIDER=edgegap` remains production. `aws-proving` selects `ec2`, with its own Registry/Fleet
objects and D1 database. There is no provider fallback. `provider.ts` owns the common interface;
`ec2.ts` implements it using EC2 Query API 2016-11-15 and WebCrypto SigV4. No SDK was added: none
was installed, and these requests need only form encoding, SHA-256/HMAC and a bounded XML reader.

The Worker signs POSTs to the Singapore EC2 endpoint for exactly these actions:

- **RunInstances:** one production type from `production-server.json`, On-Demand explicitly,
  default tenancy, native `resolve:ssm:` of setup's current Ubuntu 26.04 public parameter. Each
  ordered offering subnet is tried on a capacity refusal. The primary network interface names the
  configured security group, gets a public address and is deleted on termination. IMDSv2 is
  required, the metadata endpoint enabled, hop limit one. The explicit root mapping is gp3 with
  its measured device and size, and the policy's included-baseline IOPS/throughput. Root deletion,
  instance-initiated shutdown = terminate, and API termination protection = false are explicit.
  Instance, volume and interface each carry `Project=overmatch`, `Purpose=host`, Claim and Version.
- **DescribeInstances:** either the known instance, or all pages filtered by both ownership tags
  and the non-terminated states. Reads supply the public address, current state, claim and version.
- **TerminateInstances:** the known instance. An accepted `shutting-down` response keeps its row
  and admission slot; later attempts continue until termination or accepted absence is confirmed.

The policy permits the shutdown-behaviour field: its RunInstances grants have no restriction on
that field. No policy permission was widened. `CreateTags` and `ssm:GetParameters` remain IAM
permissions consumed as part of native launch, not extra Worker API actions.

A single Fleet Durable Object owns durable admission across versions. It counts pending slots
and tagged machines not represented by them; the count/insert has no intervening await. The
owner's cap, start-attempt budget and lifetime live in `backend/aws-hosting.json`. Slots survive
object eviction and remain occupied while termination is unconfirmed. The sweep removes orphan
machines and stale orphan slots, including owned machines with missing/invalid version or claim
metadata. It preserves a live or stopping Registry claim and defers decisions when reads fail.

## Boot and release

The Registry's first join verifies the public release checksum line and archive existence (HEAD),
then stores the URL and checksum in its SQLite catalog. Concurrent joins share the fetch; successful
metadata survives eviction. Missing releases are cached for one minute (Resolution: limit repeat
reads without permanently refusing a subsequently published tag); other failures can be retried.
A missing or unverifiable release refuses `/v1/join` before creating a ticket, slot or AWS request.

`backend/scripts/embed-host.mjs` embeds the tracked `scripts/aws/machine.sh` verbatim in
`host.generated.ts`, alongside setup-owned region/parameter/tags, the server-owned port and
policy-owned gp3 limits. Tests, typecheck and Wrangler's build command refuse stale generated bytes.
CI scope includes every embedding input. The provider substitutes the one settings marker and
UTF-8/base64 encodes the result as user data; it checks EC2's user-data byte limit before launch.
The harness still uses that same script.

The hosted role installs no package or SSH key. It writes a root-only environment/header, verifies
and unpacks the archive, and starts the existing server binary. Its systemd ExecStopPost runs with
root permission and requests power-off on every service exit. The launch's terminate-on-shutdown
and delete flags complete that guard. An independent scheduled power-off uses the owner's lifetime.
A boot-step failure posts an authenticated `end` naming only the step, then powers off even if the
report failed. The verified archive remains on the ephemeral root until termination. No journal
upload was added.

MEASURED by this lane's read-only image check: the current public image has `/dev/sda1`, **8 GiB**,
gp3. `scripts/aws/host-image.json` owns that measured root contract. Setup checks discovery against
it before mutation; a changed root requires review and rebuilding the Worker, without pinning an
old image or widening the key. The Worker cannot discover the root dynamically because its policy
does not grant DescribeImages. Actual audio-free release extraction and remaining filesystem space
are **unmeasured offline**: the normal live end-to-end on the explicitly sized root proves fit.

No Rust change was needed. The public address and server-owned UDP port fit the existing ready
answer; tickets, netcode key, report secret, heartbeat and `/v1` request/response shapes are unchanged.
The proving adapter supplies Singapore through the existing location interface. The client picker,
ping probe and production Edgegap path remain. EC2 admin cost is explicitly unknown, since the
existing dashboard rate prices Edgegap rather than AWS.

## Failures and outcomes

| Input/failure | Deliberate outcome |
|---|---|
| Missing checksum or archive | Join HTTP 404: `no server release exists for this version`; no AWS request |
| Network/GitHub error, malformed/misnamed/oversized checksum | Join HTTP 503: `the server release could not be verified`; no AWS request |
| Missing/malformed host configuration or credentials; oversized user data | Definite refusal; waiting ticket fails with the existing provider-refused reason |
| Global cap reached | `no capacity in the selected location`; no RunInstances |
| `InsufficientInstanceCapacity`, `InsufficientHostCapacity`, `InstanceLimitExceeded`, `VcpuLimitExceeded`, `InsufficientFreeAddressesInSubnet` | Definite capacity refusal; try remaining subnets, then no-capacity ticket failure |
| Auth/permission/signature errors; invalid/missing/unsupported launch parameters, image, block mapping, subnet/group/key; idempotency mismatch; account blocked/pending verification | Definite refusal, no alternative provider, provider-refused ticket failure |
| Internal/service errors, throttling/request limits/timeouts, unknown future codes, malformed XML, oversized/stalled response or lost connection | One bounded retransmission with identical fields and ClientToken; if still unknown, retain claim/slot/tickets and reconcile by claim tag |
| `InvalidInstanceID.NotFound` before the Registry's start/visibility deadline | Unknown, not evidence of termination; poll/stop retries retain ownership |
| Same absence after that deadline, or explicit terminated state | Accepted absence/termination; stop completes and slot can be released |
| Address but no first authenticated heartbeat | Ticket remains `starting` |
| First silent start deadline or reported boot-step failure | Terminate and wait for confirmation, then one fresh machine in the same location; tickets remain `starting` |
| Second silent start deadline | `the server did not become ready in time`; no third machine |
| Second reported boot-step failure | `the server failed to start`; no third machine |
| Server end/crash or ready server's heartbeat expiry | Stop-until-confirmed; existing end/crash/lost reason; service exit also powers off |
| Stop denied, unconfirmed, or unanswered | Keep stopping row and slot, log failure kind, retry from the alarm/sweep |
| Sweep listing/status/Registry read failure | Log kind and defer the affected decision; never infer orphan ownership from a failed read |

The refusal table's launch-code allowlist is explicit in `ec2.ts` and covered by individual cases.
EC2 classification never uses HTTP status to infer refusal. Bodies/messages, signed headers,
provider credentials and join tickets are not logged. Response text is bounded before XML parsing;
DTDs/external entities are refused. One launch operation is bounded as a whole, including admission
and retransmission, so a timed-out continuation cannot start a later subnet launch.

EC2 NotFound and empty tag lookups are eventually consistent. The existing Registry design accepts
absence after its start window; that operational bound is not a mathematical guarantee of AWS
visibility. New-instance NotFound is not accepted early. A leaked key can still create protected
machines or retained volumes and generate egress: this slice does not claim that the cap/sweep is a
spending cap or that revoking the key cleans those resources.

## Exact live proof for the orchestrator (not run by this lane)

Prerequisites: independent lens review and merge; owner billing alert; a published **audio-free**
release whose version/content match the Rust test checkout. Do not substitute an unpublished local
version: refusal without a machine is the intended result. Ensure the proving `/admin*` path uses
the configured Cloudflare Access application; the Worker also verifies its assertion.

1. **Deploy the proving Worker and migrate its separate D1 database**, from `backend/`:

   ```sh
   npm ci --ignore-scripts --no-audit --no-fund
   npx wrangler deploy --env aws-proving
   npx wrangler d1 migrations apply DB --remote --env aws-proving
   ```

   This creates/updates `overmatch-backend-aws-proving`, its Registry/Fleet class registrations and
   scheduled sweep, and auto-provisions the separately named proving D1 database if absent.
   Registry/Fleet objects materialize when used. It creates no AWS resource. The absent AWS secrets
   deliberately refuse EC2 calls until handoff; production remains Edgegap.

2. **Issue the key to that deployment**, from repo root with pinned Wrangler on PATH:

   ```sh
   export PATH="$PWD/backend/node_modules/.bin:$PATH"
   scripts/aws/host-setup issue-key --env aws-proving
   scripts/aws/host-setup verify
   ```

   This creates one IAM access key on the existing standing user and forwards its pair plus network
   configuration to the three proving Worker secrets. It creates no machine. Verification is
   read-only. The standing group/user/policy are not recreated by issue-key.

3. **Prove authorization before launching.** Through the authenticated proving admin application,
   POST `/admin/aws-proof` with `{"version":"<published version>"}`. Then obtain the current AMI via
   a captured, read-only `aws --profile overmatch --region ap-southeast-1 ssm get-parameter` for
   `PARAMETER` in `host_setup.py`, and POST the same body plus `imageId`, without printing identifiers
   or credentials. Both responses must be `proof=authorized`, `creates=false`. Every configured
   subnet must pass; the handler accepts only AWS's `DryRunOperation`. These calls create nothing.
   A logged failure kind refuses the proof; do not widen the policy to make it green.

4. **Run the existing hosted end-to-end**, from a leased build bay with that released version:

   ```sh
   set -o pipefail
   OVERMATCH_API="$proving_url" scripts/serial-cargo test --locked --lib \
     --features dev_ui,bitprobe two_clients_join_the_same_hosted_match \
     -- --ignored --nocapture 2>&1 |
   python3 -u -c '
   import re, sys
   sys.path.insert(0, "scripts/aws")
   import harness
   for line in sys.stdin:
       if re.search(r"secret|token|ticket|authorization|private.?key|netcode.?key", line, re.I):
           print("[credential line redacted]")
       else:
           line = re.sub(r"\b[0-9a-f]{64,}\b|\b(?:AKIA|ASIA)[A-Z0-9]{16}\b", "[credential]", line, flags=re.I)
           print(harness.scrub(line), end="")
   '
   ```

   Set `proving_url` to that deployment's HTTPS origin. The sanitizer is necessary because the
   existing Rust test prints its server address. The join creates a ticket and Registry claim,
   one Fleet slot, and one instance/root volume/network interface; the second client must share
   that match. Success proves the release fits the explicit root, boots without package installs,
   reports, and serves the unchanged client contract. Cold-boot/WAN times remain observations.
   The forced-silent-boot and second-failure paths are proven offline; this normal live run does
   not by itself measure a real no-network boot rate or recovery independence.

5. **Drain and prove teardown.** Let both clients leave, wait for the configured empty exit and
   confirmed termination, then a sweep. `/admin` must show no live/stopping server and a clean
   sweep. From repo root, print counts only with the existing setup reader:

   ```sh
   python3 - <<'PY'
   import sys
   sys.path.insert(0, "scripts/aws")
   import host_setup as h
   h.identity_account()
   resources = h.tagged_resources()
   for kind, rows in resources:
       print(kind, len(rows))
   if any(rows for kind, rows in resources if kind != "SecurityGroups"):
       raise SystemExit("host resources remain; teardown proof refused")
   PY
   scripts/aws/host-setup teardown --env aws-proving
   ```

   The count proof is read-only. Every ephemeral host-resource count must be zero; the standing
   security group is expected before teardown. Teardown creates nothing: it revokes the key,
   removes the three Worker secrets, policy, IAM user and host security group, then proves AWS
   absence. It refuses rather than terminating a live match. Proving Worker/D1/history remain;
   production is unchanged. Standing parts can be reapplied keylessly for the next live slice.

## Design claims corrected or limited

- The audio-bundling/apt recommendation is superseded: the release server has no audio dependency.
  The old boot-time estimate is not a measurement of this audio-free path.
- `Purpose=match`, the proposed `hosting.sh`, and the smaller policy sketch are superseded by the
  landed host setup: `Purpose=host`, all offering subnets and explicit launch constraints. The key
  has five IAM permissions; the Worker itself calls three EC2 actions.
- A per-version Registry alone cannot enforce the global two-server decision. A shared durable
  admission owner is necessary; counting DescribeInstances results alone would race.
- Accepted termination does not mean terminated. Replacement/slot release waits for confirmation.
  New-instance NotFound is also not immediate evidence of absence.
- Current image selection does not supply root size/device with this key's permissions. The root
  is a separately measured, setup-checked contract. Setup refuses any root change; EC2 refuses a
  root larger than the explicit request. A smaller upstream root cannot be detected by this key
  before launch without a fresh operator verification; no dynamic root discovery is claimed.
- A no-network timeout must preserve the location, and late tickets on the second boot must inherit
  that boot's retry budget. Merely stopping location exclusion allows a late joiner a third boot.
- "A published client has no missing-server window" needs a qualification: a previously negative
  release lookup can remain cached for up to one minute after publication.
- The two-machine quota is not a leaked-key spending ceiling. Egress, retained volumes and API
  termination protection remain the documented security-review residuals. A launch template can
  constrain resource overrides, contrary to the design's claim that it cannot shrink abuse; adding
  one was not authorized here, and no permission was widened.
- "No machine outlives its match" describes independent cleanup mechanisms, not an absolute promise
  against Worker/API failure or a malicious key holder. Live IAM context, native resolution,
  filesystem fit, end-to-end play and timing still require the explicit proof above.
